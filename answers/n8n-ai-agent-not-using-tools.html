Why is my n8n AI agent not using its tools?

Short answer: An n8n AI Agent skips its tools when the model decides it can answer without them, which happens more with smaller models, vague tool descriptions, and long prompts. The fix is to use a model with strong tool calling, write a clear description for every tool, keep n8n updated, and split must-happen steps into their own part of the workflow so they never depend on the agent choosing them.

Why this happens

In n8n, the AI Agent node decides on its own whether to call a tool. If the model thinks it already knows the answer, it may write a reply instead of checking your sheet, calendar, or database.

Smaller or local models are more likely to skip tools or return broken tool calls. n8n also released a fix in version 2.40.0 for an issue where some providers were not told to call a tool on the first step.

When the agent quietly skips a tool, the workflow can still look successful, which is why people describe it as working half the time.

How to fix it, step by step

  1. Update n8n to a current version.
  2. Switch the agent to a model known for reliable tool calling and test again.
  3. Give each tool a clear name and a one-sentence description of exactly when to use it.
  4. Shorten the system message so the tool rules are easy to find.
  5. Turn on intermediate steps so you can see whether a tool was actually called.
  6. If a step must always happen, like looking up inventory, move it out of the agent and run it as a normal node before the agent replies.
  7. Add a check before any email or message goes out, so a reply without real data gets stopped.
  8. Set a low maximum number of iterations and avoid automatic retries that could loop and use up API credits.

Common questions

Why does my n8n agent work sometimes and not other times?

The agent chooses whether to call a tool each time, so the same request can go either way. Moving required steps out of the agent makes the workflow predictable.

Which model works best with n8n tools?

Results vary by model and by version, so test with your own workflow. Users consistently report that larger hosted models call tools more reliably than small local models.

Can an n8n agent get stuck in a loop?

Yes. Retries and high iteration limits can cause an agent to repeat a failing step many times. Setting a low iteration limit and adding a stop condition prevents runaway costs.

Do I need to know code to fix this?

Not always. Many fixes are settings and workflow changes inside n8n. If the workflow is complex, a second pair of eyes can save a lot of trial and error.
